- Keep VPN tunnel behavior explicitly simulated in the web interface; real tunneling requires a native VPN service and Xray core.
- Parse configuration links and QR images locally in pure TypeScript; keep credentials out of AI recommendation payloads.
- Keep optional Gemini keys session-only and send them only to the same-origin server function for provider requests.
- Model client sections as in-place instrument tabs, with protocol parsing and export isolated from presentation components.
- Express machined surfaces and incised typography through shared semantic CSS material tokens and client selectors so all tabs and dialogs stay visually consistent without changing connection logic.
- Keep public-directory ingestion and personal rating persistence in a browser-safe module separate from UI; direct source fetches avoid relaying configuration credentials through our server.
- Keep the external Android VPN adapter as a typed contract only until an actual service is supplied; fail unavailable rather than treating simulated protection as native enforcement.
- Import the client logo from a shared bundled raster asset and derive the public favicon from its emblem; this keeps the header and browser identity consistent without altering VPN logic.
- Derive platform icons from the same Netcon emblem, keeping adaptive foregrounds mask-safe and store icons opaque; shared artwork prevents inconsistent brand marks across installations.
- Keep welcome artwork and copy in a shared browser-safe slide module; open the skippable first-visit dialog after hydration and allow replay from Info without resetting client state.
- Keep translations in a browser-safe dictionary and a shared language context; persist the choice after hydration and translate presentation labels without changing protocol values, server credentials, or brand names.
- Keep the shared collapsible settings dashboard separate from network configuration and diagnostics; app help and appearance must not change tunnel or server state.
- Register the app service worker only through src/lib/pwa-register.ts (never in dev, Lovable previews, iframes or with ?sw=off); PWA packaging (PWABuilder) depends on the generated /sw.js and the manifest staying complete.
